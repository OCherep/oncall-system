# Зняття відсутності на конкретну добу

Окремий день із вже затвердженої відсутності зняти неможливо. Заявка — це один запис з діапазоном `start_date`–`end_date`, без виключення окремої дати і без кнопки «зняти цю добу».

Обхідний шлях: відхилити всю заявку і створити нову з потрібними датами. Графік чергувань перерахується сам.

## Що саме перераховується

- Лише дні **від сьогодні (Київ) і далі**, до кінця наступного місяця.
- Минулі дні **не змінюються**.
- Дні, правлені адміном уручну (`is_manual = 1`), лишаються.
- У розрахунок потрапляють лише заявки зі статусом `Approved`.
- Відхилення затвердженої заявки й створення нової зі статусом `Approved` кожен викликає `regenerateFutureShifts`.

Якщо нову заявку залишити в `Pending` і не затвердити, людина в майбутньому графіку вважатиметься доступною.

## 1. Знайти заявку

Адмінка → **Менеджмент** → **Для затвердження**.

-Якщо заявка ще **Pending** — вона в блоці «Очікують», є кнопка **Відхилити**.
- Якщо вже **Approved** — кнопки немає (у діях стоїть «—»). Id треба взяти з API.

Увійти як admin, відкрити консоль браузера на сторінці OnCall:

```javascript
fetch('/api/admin/requests', {credentials:'same-origin'}).then(r=>r.json()).then(list =>
  console.table(list.filter(a => a.status === 'Approved').map(a => ({
    id: a.id, user: a.user_name, type: a.type, from: a.start_date, to: a.end_date
  })))
)
```

## 2. Відхилити стару заявку

**Pending:** кнопка **Відхилити** в блоці «Очікують».

**Вже Approved:** той самий виклик з консолі (підставити `id`):

```javascript
fetch('/api/admin/requests', {
  method: 'PUT', credentials: 'same-origin',
  headers: {'Content-Type':'application/json'},
  body: JSON.stringify({id: 123, status: 'Rejected'})
}).then(r => r.json()).then(console.log)
```

Або з хоста, якщо є сесійна cookie:

```bash
curl -sk -b "$COOKIE" -X PUT 'https://s.ks.tv:85/api/admin/requests' \
  -H 'Content-Type: application/json' \
  -d '{"id":123,"status":"Rejected"}'
```

Після цього майбутні чергування перераховуються **без** цієї відсутності.

## 3. Створити нову з іншими датами

Там само, **Для затвердження** → **Додати відсутність** (admin / тім-лід / PM):

- та сама людина і тип;
- нові дати (наприклад замість 1–10 листопада — дві заявки: 1–4 і 6–10, якщо треба зняти 5-те);
- статус **Approved** або галка автозатвердження.

Після збереження графік перераховується ще раз. Оновити календар.

## Приклад

Відсутність `devops2`, 1–10 листопада, вже `Approved`. Треба, щоб 5 листопада людина була доступна.

1. Знайти `id` старої заявки.
2. `PUT /api/admin/requests` з `{"id":…,"status":"Rejected"}`.
3. Додати дві нові: 1–4 і 6–10, обидві `Approved`.

## Що цього не робить

- Не вирізає один день із існуючого діапазону.
- Не переписує минулий графік.
- Не чіпає дні з ручною позначкою.
